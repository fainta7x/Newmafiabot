# Пилот гардероба на оригинальной аватарке Dendi — PR #891

**Статус: отдельный тестовый прототип, не опубликованная косметика и не утверждение пользовательского дизайна.** Исключительно инженерная основа для обратной связи владельца.

## Исходник

`public/player-avatars/dendi.jpg` — настоящий JPEG аватарки Dendi из текущего проекта. Сохранённое лицо/волосы **не генерируются заново нейросетью**. Для данного исходника сделана репродуцируемая ручная альфа-маска. Не применять её автоматически к портретам других людей.

```bash
node scripts/buildDendiPortraitLayers.mjs temp/dendi-portrait-layers
node scripts/buildDendiWardrobePreview.mjs temp/ui-preview/dendi-wardrobe.html
```

Первая команда извлекает **два** отдельные PNG RGBA по 512×640 (общие координаты):
- `dendi-face-hair-base.png`: защищённая голова, лицо и волосы. **Не заменяется** предметом одежды.
- `dendi-original-suit.png`: исходный бордовый костюм вместе с рубашкой, бабочкой и руками как **один временный базовый силуэт одежды**, отдельно от головы.

В `manifest.json` указаны SHA-256 исходного JPG, размеры и порядок композитинга. Любое обновление исходного JPG требует проверки новых масок, не бесшумной перегенерации.

**Важно:** разбиение не означает автоматического получения всех скрытых исходником деталей. В исходном JPG рубашка, жилет, руки, галстук-бабочка и пиджак частично перекрывают друг друга. Пока пальцы и бабочка визуально входят в один слой исходного костюма. Нельзя выдавать их за независимые готовые предметы или обещать правильное переодевание без ручной ретуши и отдельных артов. Новый головной убор в тесте — только ранее существовавший черновой `autumn-fedora-v1.svg`, не одобренная награда и не квота предметов.

## Пользовательский экран

`src/components/player/DendiWardrobePrototype.tsx` — **отдельный, player-first** интерфейс: персонаж крупно; переключение Мирный/Мафия/Дон/Шериф; самостоятельные слоты; отдельные кнопки «надеть/снять»; просмотр исходной аватарки и сравнение четырёх ролей. На мобильном слоты и миниатюры компактные, мастерская администратора отсутствует. Слоты без корректных ассетов показаны, но не могут экипировать несуществующие вещи.

**Сохранение в пилоте только в памяти текущей страницы.** Не вызывает боевое API, не изменяет `player_role_looks`, не сохраняет черновики клуба, не добавляет предметы в каталог, магазин и награды. Отдельная настоящая система `equippedItems` существует в PR, но дизайн пилота в неё до одобрения владельцем **не встроен**.

Вариант для скачивания/прокликивания: GitHub Actions → PR #891 → workflow `UI preview` → артефакт `ui-preview-site` → `dendi-wardrobe.html`. Автономный HTML содержит встроенные PNG из реального JPG. В CI добавлены сценарии для экранов 390 и 1440 пикселей, по отдельным четырём ролям, без горизонтального переполнения.

## QA перед интеграцией в боевой профиль

1. Проверить PNG на тёмном, светлом и шахматном фоне; убрать светлые фрагменты обводки от исходного баннера, ровно подогнать линии волос и воротника.
2. На оригинальном лице Dendi проверить головной убор в разных ракурсах, перекрытия лба и глаз; не считать существующий SVG готовым для награды.
3. Раздельно разработать контракт для вариативной **рубашки, пиджака, аксессуаров и элементов рук**. Технический слой «оригинальный костюм» — временный начальный пример, а не окончательная структура сетов.
4. Проверить две и более аватарки игроков и мобильные экраны перед активацией в клиентском профиле.
5. Отдельно согласовать графический дизайн и редкости конкретных вещей. Владелец утвердил пять сетов (2 common, 2 rare, 1 legendary) как коллекции, **не** состав/количество их независимых вещей.

**Не мержить и не деплоить до визуального одобрения владельцем.**
