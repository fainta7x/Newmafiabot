# Подробности показателей, совместные игры и цели

Следующий связный проход после CT01–CT15. Основание: владелец просит продолжать анализ и улучшения этих разделов во время проверок #1072. Полный разбор трёх направлений завершён до правок приложения; это развитие уже выбранного содержательного фокуса. Текущий статус — в PROJECT_STATE.

| Код | Проверенная трудность | Решение и имеющиеся данные |
| --- | --- | --- |
| CD01 | В подробностях решений шесть панелей показывают отдельные числа целей без общего количества и визуального соотношения. Шериф — часть красных, не ещё одна независимая группа. | В каждой панели — общее количество, распределение красные/чёрные/неизвестно и отдельная подпись шерифа внутри красных. Использовать TargetCounts; неизвестных по-прежнему не включать в точность. Никакого нового рейтинга. |
| CD02 | API связей уже передаёт три последние общие партии, но экран их не использует. Игрок видит общий счёт без конкретного контекста. | В собственных связях показать эти партии: дата, название, одна команда или соперники. Совместный исход только там, где есть точный won_together; игры против не объявлять поражением. Канонический источник известен из id. На чужом профиле историю не расширять. |
| CD03 | Совместные победы в списке скрыты при одной-двух играх в команде, хотя данные передаются; старый ответ без поля трактуется как0. Выделенная карточка называется «Лучший напарник» по сырому винрейту. | Показывать известные победы с знаменателем для любой имеющейся игры, не выдумывать отсутствующий0. Фактическая подпись «Победы с напарником» без утверждения об общей силе. Условия попадания в серверный список не меняются. |
| CD04 | Список связей — до24 частых встреч от двух общих игр, а счётчик может восприниматься как весь круг игроков. | Передать существующие ограничения как метаданные из того же владельца, не считать новый агрегат. Подписать охват/всю историю, сохранить поиск и разные основания сортировки. Старому ответу не приписывать неизвестные ограничения. |
| CD05 | Условие цели может относиться к партии, вечеру, турниру или карьере, но это приходится вычитывать из абзаца. | Короткая контекстная подпись из канонического каталога историй. Формулировки условий и алгоритм награждения неизменны. Подтверждённые приглашения — отдельный контекст. |
| CD06 | Общий счёт2/16 не объясняет состояние выбранного пути. У «Четырёх лиц» список ролей не назван списком ролей с победой; завершённый путь выглядит просто как набор карточек. | Счёт полученных историй именно выбранного пути; честное сообщение при полном завершении; явная подпись ролей с победой. Не добавлять процент для разового условия и не придумывать отсутствующий прогресс. |

Проверены: все шесть панелей действий; собственные/публичные/ограниченные связи, игроки/команда/приглашения, все/напарники/соперники и охват серверной выдачи; все16 историй и6 путей, условия их вычисления, известный прогресс, полученные и закреплённые карточки/каталог. Новая передача метаданных не меняет eligibility, сортировку или24-строчный предел. Сервисы рейтинга и начисления наград не редактируются.

Не входят: новые игровые советы/агрегации, общая оценка силы напарника, перенос фильтров Обзора на все связи, публичная детализация чужих партий, переписывание спортивных терминов или условий наград. Данные для этой работы уже существуют; точность и приватность сохраняются.

Владельцы: `PlayerGameNumbers`/`TargetCounts`; `PremiumProfileConnections`, `playerConnectionAnalyticsService`, `premiumPlayerConnectionProfileService`; `PlayerAchievementPaths`, `achievementStories`, `playerAchievementStoriesService`. Последний прочитан для проверки смысла, без изменения вычислений.

Приёмка будущего изменения: суммы распределения не считают шерифа дважды; неизвестное не выглядит0; история игры против не выдаёт ложный исход; чужой профиль не раскрывает новую историю; счёт пути относится к выбранным карточкам; тип цели совпадает с её существующим алгоритмом. Проверки затронутые и обязательный layout gate, без общего поиска ошибок.
