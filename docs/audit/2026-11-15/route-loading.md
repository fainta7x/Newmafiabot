# Первоначальная загрузка сайта и кабинета

Измерение исходной production-сборки c01994d: статический граф index.html загружает 11 JS-файлов, всего 1,234,881 байт; gzip level 6 по отдельным файлам — 336,754 байт. В графе есть профиль, кошелёк, календарь и другие части кабинета, хотя публичный сайт их не использует.

После переноса PlayerCabinetShell на существующую границу React.lazy: 6 первоначальных JS-файлов, 403,195 байт; gzip — 121,571 байт. Это −67.3% исходных байтов и −63.9% gzip-байтов. Учтены все статические imports entry, а не только файл index-*.js. Измерение относится к передаваемому JS, не к полному размеру сайта, времени загрузки или скорости CPU.

Кабинет подгружается одновременно с bootstrap авторизации для /player и Telegram-контекста корня. Для публичных страниц и admin этот preload не запускается. Существующие Suspense, возврат на сайт и восстановление после vite:preloadError сохранены. Разметка и стили не менялись.

## Проверка

- 5 исходных browser/layout сценариев /welcome до изменения проходят.
- После изменения проходят 8 сценариев: /welcome и форма на 360×640, 390×844, 1366×768, 1440×900, 1920×1089 без загрузки PlayerCabinetShell; /player на 390 и 1440 с удержанием auth-response до начала загрузки чанка, затем вход и reload; недоступный чанк до обновления документа с успешным восстановлением после reload.
- В тесте недоступный asset остаётся 404 в исходном документе (включая modulepreload retries) и становится доступен только после reload. History.replaceState нельзя считать перезагрузкой; используется Navigation Timing.
- API полностью подменено в локальном production preview. Service workers заблокированы для детерминированной подмены сетевых отказов; реальная Telegram/VK-авторизация и production-трафик не проверялись. Существующий обработчик восстановления чанков не менялся.
- Снимки страницы /welcome до/после на 390 px просмотрены: содержимое и расположение элементов сохранены.

Воспроизведение замера:

```bash
npx vite build --manifest
node scripts/measureInitialRouteChunks.mjs dist
npx vite preview --host 127.0.0.1 --port 4176 --strictPort
```

В другом терминале после установки зависимостей e2e и Chromium:

```bash
ROUTE_BASE=http://127.0.0.1:4176 e2e/node_modules/.bin/playwright test --config=e2e/route-loading.config.mjs
```

Для системного Chromium можно задать ROUTE_BROWSER=/usr/bin/chromium. Без этой настройки используется установленный браузер Playwright. Три теста чанков требуют production preview и вне специального config пропускаются; обычные dev-harness не имеют хешированных чанков. Базовый и итоговый JSON сохраняют состав фактически измеренного статического графа.

Кандидат требует GitHub checks и отдельного подтверждения выкладки. Измерения стенда не означают, что production уже ускорен.
